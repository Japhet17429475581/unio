# MyTracker в UNIO (Android)

Подключён официальный `com.my.tracker:mytracker-sdk:3.5.0` через Maven Central.
Версия соответствует диапазону `[3.5.0, 3.6.0)` из предоставленного
`build/app/androidsdk/build.gradle`. Эта папка содержит Android-часть Flutter-плагина,
а не автономный SDK: она тоже загружает нативную библиотеку из Maven.
Зависеть от `build/` нельзя — она удаляется командой `flutter clean`.

Документация: [Android SDK](https://docs.tracker.my.com/ru/sdk/android/api),
[официальный Flutter-плагин](https://github.com/myTrackerSDK/mytracker-flutter).
API конфигурации дополнительно проверен по `classes.jar` версии 3.5.0.

## Подключение и режимы

- `android/app/build.gradle.kts`: закреплённая версия SDK, параметры сборки.
- `UnioApplication.kt`: единственная инициализация в `Application.onCreate`,
  SDK-ключ `01871019976186749436` хранится строкой с начальным нулём.
- `AnalyticsChannel.kt`: небольшой канал Flutter → Android с закрытым списком
  имён событий, параметров и их значений.
- `lib/services/analytics_service.dart`: типизированные события без произвольных
  строк. Ошибка аналитики не блокирует вход, сохранение или отправку заявления.
- `lib/main.dart`: неблокирующая проверка доступности канала при запуске.

В release аналитика включена. Обычные debug-запуски и Flutter-тесты не отправляют
события. Для проверки на Android-устройстве:

```powershell
flutter run --dart-define=MYTRACKER_DEBUG=true
```

Этот режим отправляет тестовые события в тот же проект MyTracker, включает SDK-логи
и сокращает накопление событий до 5 секунд. Для отдельной тестовой статистики нужен
отдельный SDK-ключ приложения. В обычном релизе период накопления — 300 секунд.
Буферизация и доставка при восстановлении сети делегированы SDK, своего фонового
планировщика и дополнительных таймеров отправки нет. Запуски и сессии собирает SDK;
вручную второй `app_open` не отправляется.

Отключить SDK для всей сборки:

```powershell
flutter run --release --dart-define=MYTRACKER_ENABLED=false
```

iOS, web и desktop пока не подключены: сервис работает как no-op. Для iOS нужен
свой SDK-ключ и отдельная нативная интеграция.

## События

| Событие | Когда / параметры |
|---|---|
| `onboarding_started` | Показ первого знакомства |
| `onboarding_finished` | `action`: `completed` / `skipped` |
| `role_selected` | `role`: `student` / `teacher` |
| `login_attempt` | После локальной проверки полей; `role`, `method`: `guest` / `portal` |
| `login_result` | `role`, `method`, `outcome`: `success` / `failed` |
| `logout` | После удаления локальной сессии; `role` |
| `screen_view` | Открытие раздела; `screen`, иногда `role`. Не при каждом rebuild и не для скрытых вкладок IndexedStack |
| `week_changed` | Завершённое переключение недели кнопкой/свайпом; `role`, `action`: `next` / `previous` |
| `note_saved` | Результат явного сохранения; `outcome`, `has_photos`: `true` / `false` |
| `request_create` | `outcome`: `attempt`, затем `success` либо `unconfirmed` |
| `request_submit` | После подтверждения отправки: `attempt`, затем `success`, `rejected` либо `unconfirmed` |
| `template_saved` | Шаблон действительно сохранён, отмена диалога не считается |
| `guide_opened`, `guide_completed` | Открытие / завершение единого гайда; `role` |
| `news_story_opened` | Открытие короткой новости |
| `news_full_opened` | Открытие полного текста из ленты или истории |
| `teacher_selected` | Выбор преподавателя в поиске без ФИО / текста поиска |
| `rooms_search` | Открытие поиска аудиторий преподавателем |
| `setting_changed` | `setting`: `dark_theme` / `push`; `action`: `enabled` / `disabled`, только после успеха |
| `notification_opened` | Переход из локального уведомления; `screen`: `schedule` / `requests` |

`unconfirmed` означает отсутствие подтверждения от портала: запрос мог быть принят.
Это не отказ и не основание автоматически повторять отправку. Результат создания
не означает готовность справки: готовность определяется существующей логикой портала.

## Что смотреть в кабинете

1. Запуски, активные устройства, удержание по дням и версиям приложения.
2. Воронка знакомства: начало → завершение/пропуск → роль → успешный вход.
3. Доля успешных входов по способу и роли (`login_result` относительно `login_attempt`).
4. Использование разделов (`screen_view`, разбивка `screen`) и заметок.
5. Воронка заявлений: `request_create/outcome=success` → `request_form` →
   `request_submit/outcome=attempt` → `success`. `unconfirmed` смотреть отдельно.
6. Переходы из коротких новостей в полный текст и прохождение гайда.

Это схема для настройки отчётов в кабинете; сами отчёты в аккаунте не создавались.
Идентификация привязана к установке/устройству SDK, а не к учётной записи ВГСПУ:
метрики устройств нельзя выдавать за точное число уникальных студентов.

## Данные

В события не передаются логины, пароли, токены, ФИО, группы, поисковые строки,
адреса, номера/типы заявлений, текст заметок, фотографии, вложения и тексты ошибок.
Не вызываются API `customUserId`, `email`, `phone`, `age` или `gender`.

Отключены геолокация, сбор окружения, датчики AntiFraud, предустановки и автосбор
платежей. Исключены зависимости рекламного идентификатора и Billing; разрешения
AD_ID и BILLING удалены из объединённого манифеста. Install Referrer и App Set ID
остаются техническими зависимостями SDK. Сам SDK собирает техническую информацию
об установке/устройстве и сессиях; это не обещание полной анонимности.

## Приёмочная проверка

На реальном Android-устройстве включить тестовый режим, пройти вход, открыть
расписание/новости, сохранить тестовую заметку, сверить события и параметры в
кабинете. Затем отключить сеть, выполнить действие, восстановить сеть и проверить
доставку SDK. Повторно запустить приложение: должна появиться новая сессия по
правилам SDK, без повторной инициализации внутри одного процесса.

Автотесты `test/analytics_service_test.dart` проверяют однократную инициализацию,
типизированные параметры, отключённую сборку и отказ/отсутствие нативного канала.
Доставку в кабинет подтверждает только проверка на устройстве с доступом к MyTracker.
