# UNIO PWA — beta.2

22 октября 2026 года. Общий Flutter-интерфейс: гостевой и университетский вход, режим преподавателя, расписание, новости/сторис, успеваемость, заявления, Word-шаблоны, вложения, заметки и фотографии. MyTracker в PWA не запускается; Android-виджет остаётся функцией APK.

## Вход и данные

APK по-прежнему входит непосредственно в ВГСПУ. PWA обращается к `/api/v1/web-portal` на **своём HTTPS-origin**. Посредник временно обрабатывает логин/пароль и сохраняет в PostgreSQL только зашифрованные cookie университета, хеши собственных токенов, связь с аккаунтом и даты. Пароль не записывается в БД или браузер. Новые потоки отражены в документах редакции 22.10.2026 и требуют проверки оператором.

Access-cookie действует 15 минут, refresh-cookie — не более 30 дней; оба Secure/HttpOnly/SameSite Strict. Обновление заменяет токены; повтор старого refresh после короткого окна параллельных вкладок отзывает доступ. Закрытие приложения не требует нового ввода пароля. Если университет завершит свою авторизацию, придётся войти повторно: без хранения пароля или официального SSO гарантировать бесконечный доступ нельзя. Схема использует токены и серверные записи университетских cookie.

Посредник ограничивает origin ВГСПУ и разрешённые операции, проверяет Origin, служебный заголовок, размеры, частоту обращений. Cookie университета не выдаются браузеру. Личные HTML и вложения не кешируются. Изменяющие операции после сетевых ошибок автоматически не повторяются; обновление web-токена возможно только после отказа до исполнения действия в вузе.

Собственный токен UNIO, логин для разделения заметок, группа, настройки и журнал согласий находятся в браузерном storage; он не равен Keystore/Keychain. Заметки с фото — в IndexedDB. Фиксированного лимита количества фото нет в обеих версиях; остаются 10 МБ на файл и квота устройства/браузера. Браузер может очистить хранилище; важные оригиналы следует сохранять отдельно.

## Размещение

1. Обновить **весь backend**, установить `lib/backend/requirements.txt`. Миграции `002_web_portal.sql` и `003_web_push.sql` применяются существующим `init_db()` при запуске. Нужны права DDL; предварительно сделать защищённый backup.
2. На машине с backend-зависимостями выполнить `python tools/prepare_pwa_backend.py --origin https://ВАШ-ДОМЕН-PWA`. Скрипт создаст `build/pwa-backend.private.env`, не выводя секреты и не перезаписывая старый файл. Импортировать значения в **переменные окружения backend**. Не загружать файл в Git или `public/`.
3. Настройки backend: `WEB_PORTAL_ORIGINS` (точный HTTPS-origin PWA, несколько через запятую), `WEB_PORTAL_KEYS` (Fernet), `WEB_PUSH_PRIVATE_KEY`, `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_SUBJECT`. Хранить ключи стабильно вне БД с ограничением доступа. Потеря Fernet-ключа требует нового входа, смена VAPID — переподписки. При ротации Fernet старые ключи оставляют после нового через запятую до истечения прежних записей.
4. Распаковать `build/UNIO-PWA-1.0.0-beta.2.zip`, разместить **всё содержимое архива как отдельное Docker-приложение**. Внутренний порт 8080; хостинг предоставляет внешний HTTPS. `UNIO_API_UPSTREAM` — HTTPS-origin обновлённого backend без завершающего `/`; по умолчанию текущий Bothost backend. При изменении адреса backend также пересобрать клиент с `--dart-define=API_HOST=НОВЫЙ-HOST`.
5. `/api/` проксируется через домен PWA. Origin/Set-Cookie передаются без изменения, X-Forwarded-Host/Proto задаются доверенным proxy. Статический хост без `/api/` поддержит гостевые функции, но не вход через портал. Не включать CDN-кеш и запись тел, cookie, токенов и персональных query в логах/трассировке, в том числе на стороне хостинга.

Сборка:

```powershell
flutter build web --release --no-pub --no-web-resources-cdn --no-wasm-dry-run
python tools/package_pwa.py
```

ZIP обновляет сайт, **не backend**. Без настроек портал выдаёт `WEB_CONFIG`. Для статического localhost-просмотра: `python -m http.server 8080 --directory build/web`; эта команда не заменяет API proxy. На другом телефоне localhost указывает на сам телефон. Для реального доступа нужен постоянный HTTPS-домен.

## Уведомления и очистка

Web Push включается отдельным действием в настройках; браузер запрашивает разрешение. На iPhone нужно добавить UNIO на домашний экран и открыть оттуда; поддержка — iOS/iPadOS 16.4+. Источник: [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/). Камера и выбор файлов открываются при действии пользователя.

Backend проверяет расписание раз в минуту через существующий кеш; напоминания — за 60 минут до первой пары и за 10 до остальных. Статусы заявлений — раз в 30 минут при действующих cookie. Текст push общий, без ФИО, группы и содержания заявления. Подписка и снимок статусов зашифрованы в БД. Получатели доставки — службы Apple/Google/Mozilla/Microsoft в зависимости от браузера; их условия и географию необходимо проверить отдельно. Доставка зависит от ОС и связи и не гарантирует точного времени.

Выход очищает локальные credentials при сбоях и отзывает web-cookie с коротким таймаутом. Отложенный отзыв UNIO-токена также удаляет связанные web-сеансы и подписки после восстановления связи. Удаление аккаунта каскадно удаляет новые записи. Университетские документы и доставленные внешним получателям уведомления это не удаляет. Не закрывать сайт до подтверждения серверного удаления.

Сроки: web-сеанс до 30 дней и плановая очистка истёкших; неактивная push-подписка 30 дней; ключи предотвращения дублей доставки 10 дней. Сроки не определяют хранение backup, логов или данных университета.

## Кеш и проверка

Service worker хранит только список статических файлов сборки. API, портал, токены и вложения в shell-кеш не попадают. Сохранённые расписания и заметки доступны офлайн после первой загрузки. Обновление предлагается пользователю; сохраняются текущий и предыдущий shell. Размещать сборку целиком и сохранять домен.

`test_web_portal.py` проверяет origin, ограничения направлений/тела, отсутствие credentials в записи БД, cookie-флаги, обновление и повтор токенов. Flutter-тесты проверяют web-доступ без повторной отправки заявления, отсутствие сохранённого web-пароля и сохранение 17 фото. `tools/test_pwa_browser.py` проверяет release в Chrome с синтетическим API, без реальных аккаунтов. Проверки не заменяют физический iPhone и production HTTPS.

Результаты: 67 Flutter-тестов и 2 теста браузерного хранилища прошли; после доработки доступности кнопок повторно прошли 13 соответствующих UI-тестов. Backend: 43 unittest прошли. Chrome smoke: гостевой/университетский вход, успеваемость, список заявлений, сохранение входа после перезапуска, offline, обновление shell, отсутствие API в кеше, удаление аккаунта и IndexedDB; ошибок страницы и неожиданных внешних запросов — 0. Проверочный `/api/synthetic` намеренно возвращает 404. Для Chrome unit-теста в Windows пришлось подать CanvasKit из установленного SDK через Playwright: тестовый сервер Flutter возвращал 404 для этих файлов. Релиз использует собственные локальные CanvasKit assets и не требует этого обхода.

Изменённые части: `web_portal.py`, `web_push.py`, миграции `002`/`003`, `main.py`, `auth_api/auth.py`, `privacy.py`, `requirements.txt`; Flutter web-транспорт/авторизация/storage, privacy/logout, push, портал/заявления, заметки и связанные экраны; `web/pwa.js`, `web/unio-sw.js`, `deploy/pwa`, инструменты упаковки/проверки/настройки ключей. Юридические assets, backend-реестр версий и Android-версия согласия синхронизированы. Для новой PWA нужно обновлять backend целиком, а не копировать один файл.

Перед выдачей URL проверить реальные login/logout/restart, срок университетских cookie, успеваемость, категории заявлений, загрузку файла и Word-шаблон, Web Push на установленном iPhone, offline/recovery и удаление аккаунта. Реальные заявления, production-БД и миграции при разработке не запускались. Правовая оценка новых потоков и получателей остаётся за оператором/юристом.
