# Source review and repository split — 2026-11-02

This was a targeted review of the available working tree, not a guarantee that
all possible defects or security issues have been found.

## Fixed defects

1. **News cache ignored page size.** `NewsService.get_list` used one Redis key
   for differently sized responses. It now caches a complete first page and
   slices it per caller. The cache version was bumped to avoid old partial pages.
2. **Partially initialized resources survived failed startup.** PostgreSQL and
   Redis now close and reset their module-level handles after initialization
   failures. The FastAPI lifespan uses `AsyncExitStack`, so every acquired
   resource is released even when startup or another cleanup step fails.
3. **History read errors did not notify the UI.** Loading older AI messages now
   notifies listeners after resetting the loading flag, on both success and
   failure, while preserving already displayed messages.
4. **Invalid lint configuration.** Removed a reference to an undeclared lint
   package and added self-contained correctness rules. Whole-project analysis
   passes without adding another dependency.
5. **Backend tests depended on the combined workspace.** Paths now resolve from
   the test module, the notification test imports the correct package, and a
   legal-asset fixture supports independent checkout and CI.

The previously implemented parallel current/next-week timetable loading is
included in beta.11. Secure random chat IDs now reuse one generator per ID.

## Maintainability and delivery

- Separate frontend and backend repositories; the original working tree and
  staging area are preserved. No old combined Git history is published.
- English root READMEs, backend environment template, pinned runtime constraints,
  and GitHub Actions checks.
- Publication allowlists omit secrets, local configuration, logs, caches,
  original document archives, build directories, and backend code from frontend.
- APKs belong in GitHub Releases, with checksums, rather than the source history.

## Validation and remaining limits

The full initial Flutter suite passed (251 tests); the history regression suite
passed again after the final history fix (27 tests). Whole-project analysis has
no issues. The standalone backend passes 107 pytest tests and 10 subtests in a
clean Python 3.12 environment without the Flutter workspace or original PDFs.

The backend test client emits a deprecation notice about its HTTP transport;
tests pass. Android/Gradle also report upstream compatibility warnings. No live
production database, university account, real application submission, or
physical-device test was used in this review. APK signing remains the existing
closed-test configuration; public store signing needs separate configuration.

The bundled document approvals are owner test approvals, not a new independent
legal or factual review. The application still needs operator-managed hosting,
backups, secret rotation, and physical-device / production-HTTPS checks.
