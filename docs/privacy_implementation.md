# Реализация механизмов приватности UNIO

Изменения в рабочей копии от 16 октября 2026 года. Это техническая документация, а не заключение о соответствии законодательству. Production, реальные БД, портал и кабинет MyTracker при проверке не использовались. Исходные DOCX не изменены.

## Поведение приложения

- Перед первым входом и при несовпадении принятых версий открывается один экран «Документы и данные». Соглашение и согласие UNIO имеют отдельные непредустановленные флажки. MyTracker — отдельный необязательный переключатель. Отказ от аналитики не ограничивает функции. Уже сохранённая сессия не открывает персональные вкладки до принятия актуальных документов; можно выйти без принятия.
- Экран доступен из настроек студента и преподавателя. В нём находятся полные тексты четырёх переданных документов, версии и даты действий. Политика является информационным документом, отдельное согласие вместо неё не подставляется.
- В `assets/legal/documents.json` импортированы именно четыре файла с суффиксом «обновлено». В исходных текстах остались «проект» и незаполненная дата публикации. Они явно обозначены как проекты; даты вступления в силу не придуманы. Версия включает SHA-256 текста, так что изменение содержания требует повторного выбора.
- Защищённый журнал содержит UUID события, идентификатор документа, версию, SHA-256, действие, UTC-время устройства и источник действия. На сервере дополнительно фиксируются пользователь и время получения. IP и университетский пароль для доказательства согласия не добавляются. Часы устройства не считаются независимым доказательством времени. Локально сохраняются до 100 событий с сохранением последнего выбора для каждой цели; серверная запись идемпотентна по пользователю и UUID. При новом входе история предыдущего пользователя не прикрепляется к новому аккаунту. У преподавателя, для которого серверный аккаунт не создаётся, журнал остаётся локальным.
- Гостевая регистрация и запись обязательных согласий совершаются одной транзакцией. Аналитическое согласие для регистрации не требуется. Изменения согласий отправляются на сервер и повторяются при запуске/возобновлении. Отзыв MyTracker действует локально независимо от доступности сервера. Истёкший UNIO-токен требует нового входа для дальнейшей серверной синхронизации согласий; прекращение аналитики и удаление аккаунта от этого не зависят.

## MyTracker

В SDK 3.5.0 отсутствует публичный API полного завершения сбора. Поэтому SDK перенесён в неэкспортируемый Android Service отдельного процесса `:analytics`. `Application.onCreate` больше не запускает SDK. Нативный допуск хранится в `noBackupFilesDir` и содержит версию согласия и случайную метку; перед каждым запуском сервиса проверяется совпадение допуска. `START_NOT_STICKY` исключает автоматическое восстановление сбора после уничтожения процесса без нового разрешённого вызова приложения.

Отзыв сначала удаляет нативный допуск, затем останавливает/завершает процесс SDK и очищает его известные локальные БД, preferences и файлы. Главный процесс приложения продолжает работать. Неудача остановки не показывается как успешный отзыв. Flutter также отбрасывает события, ожидавшие инициализации до отзыва. Выход отключает аналитику; следующий вход требует нового выбора. Debug по умолчанию оставляет SDK выключенным; для разрешённой проверки нужен `--dart-define=MYTRACKER_DEBUG=true`, а согласие всё равно обязательно.

Сохранены allowlist событий и категориальных параметров, выключение геолокации, anti-fraud сенсоров, покупок и preinstall, исключение advertising ID. SDK debug-логи отключены. Ранее принятые MyTracker пакеты или запросы, уже переданные в сеть, невозможно отозвать задним числом. Кнопка прекращает дальнейшую работу SDK, но не удаляет серверную историю у поставщика. Для неё указан контакт обращения.

**Нужна проверка на устройстве:** отсутствие SDK-трафика до выбора и после завершённого отзыва, повторное согласие без старого буфера, запуск из фонового worker, поведение при уничтожении процесса/обновлении приложения. SDK теперь не наблюдает Activity главного процесса: автоматические метрики запусков/сессий и атрибуцию необходимо сверить с поставщиком и кабинетом. Автоматические тесты и успешная компиляция не доказывают фактический сетевой состав или качество этих метрик.

## Выход и удаление

Выход независимо выполняет удаление student/teacher credentials, запрет восстановления закрытой сессии, отмену активных прямых запросов в основном процессе, отключение аналитики и уведомлений. Ошибка одного компонента не пропускает остальные операции. Закрывается запись из редакторов, которые могли завершить асинхронный выбор файла уже после выхода. Университетский протокол входа и HTTPS-origin-проверка сохранены.

При удалении дополнительно очищаются заметки и их копии фотографий, временные файлы приложения, пользовательские preferences, кеши, снимки статусов, журнал согласий и image cache. Сохраняются только неперсональные тема/флаг знакомства, служебный запрет восстановления сессии и защищённые задания, пока действие не подтверждено. Удаление синхронизируется с записью статусов, чтобы работающий worker не восстановил очищенный снимок. Оригиналы фото, экспортированные DOCX и документы в ВГСПУ эта операция не удаляет.

Очередь повторов хранит **только UNIO-токен и вид операции**, без университетских credentials. Перед очисткой записывается защищённый маркер восстановления, который также может временно содержать этот токен. Ответ 5xx/404, отсутствие сети и тайм-аут не признаются успешным удалением. Очередь повторяется при запуске/возобновлении приложения; после подтверждения токен из неё удаляется. При незавершённой локальной очистке маркер остаётся до восстановления. Пользователь видит предупреждение не удалять приложение до подтверждения сервера. **Удаление самого приложения уничтожит очередь и не является командой удаления серверного аккаунта.**

Серверный `DELETE /api/v1/auth/account` удаляет строку `users` по хешу предъявленного токена; связанные согласия и push-токены удаляются FK cascade. Истечение срока токена не мешает этому уничтожению. Повторное удаление идемпотентно. Общедоступные новости и расписания университета не относятся к удаляемой личной записи. Ранее отозванные токены не позволяют найти старую строку: для старых/потерянных аккаунтов остаются обращение оператору и автоматическая очистка по неактивности.

## Backend и сроки

Отмонтирован весь legacy `/api/v1/portal/*`, удалён `/api/v1/auth/portal`. Текущие Flutter-сервисы используют `withPortal` напрямую; соответствующие регрессионные тесты проходят. Старые сторонние клиенты, использующие отключённые пути, получат 404. Публичные teacher API сохранены; `/teachers/login` принимает только ФИО и не является проверкой университетского пароля.

| Объект | Реализованное правило |
|---|---|
| Пользователи и связанные серверные согласия/push-токены | 90 дней с последнего принятого использования UNIO-токена, его создания либо создания пользователя; `USER_RETENTION_DAYS`, минимум 31 |
| История занятий PostgreSQL | Удаление занятий старше 90 дней; `SCHEDULE_RETENTION_DAYS`, минимум 7 |
| Планировщик серверной очистки | При запуске и далее каждый час; время недоступности сервера сдвигает фактическое выполнение |
| Локальные кеши расписаний, справочника/недавних преподавателей и новостей | 7 дней с записи; проверка при запуске/возобновлении и чтении кеша; старым кешам без даты даётся один миграционный период |
| Снимки статусов заявлений | 90 дней без обновления; отдельные ID, отсутствующие в новых ответах, также истекают через 90 дней, сохраняя работу с несколькими страницами |
| Личные заметки и фотографии | До явного удаления заметки/локальных данных; автоматического уничтожения авторских записей не добавлено |
| Redis | Существующие TTL сохранены: расписание — обычно 24 часа; rate-limit — 60/300 секунд. Это срок свежести/ключа, не срок БД и бэкапов |
| Очередь удаления/отзыва | До подтверждения сервером; без ложного удаления задания по таймеру |
| Серверные логи хостера, backups, MyTracker | Не управляются этим кодом; требуются реальные настройки и согласование сроков |

В UI указан стандартный срок неактивности 90 дней. При изменении серверной переменной необходимо синхронно изменить опубликованные документы и пользовательский текст.

Из диагностик удалены значения группы, строки исключений, тела и детали сетевых ошибок. Нештатные ответы API и ошибки валидации не отражают присланные поля. Uvicorn access log отключён; общий logging-фильтр исключает аргументы и трассировки сторонних библиотек. Flutter сообщает только постоянные коды необработанных ошибок. Из `check_db.py` убрана литеральная строка подключения — используется переменная окружения. **Git-история не переписывалась, прежний секрет не ротирован:** если он действовал, необходима отдельная смена на стороне БД.

## Android Backup

`allowBackup=false`; одновременно заданы исключения всех доменов для старого Auto Backup и современных cloud/D2D rules, включая device-protected storage. В собранном merged debug manifest подтверждены все три атрибута и отдельный неэкспортируемый процесс аналитики. APK собирается с этими XML. Ранее созданные облачные копии эти правила не удаляют; фактический restore/перенос на поддерживаемых устройствах и iOS Keychain после uninstall требуют отдельной проверки.

## Внедрение и ручные действия

1. Подтвердить финальные юридические тексты: текущие DOCX содержат проекты и описания прежних отсутствующих механизмов. Назначить дату/версию публикации, согласовать основания, обязательность основного согласия и сроки с юристом. После изменения текста пересчитать SHA-256 и версии в `assets/legal/documents.json`, `lib/backend/legal_versions.json`, а для аналитики — `AnalyticsLegalVersion.kt`. Проверка совпадения Flutter/backend есть в тестах. Не выдавать этот технический результат за правовую экспертизу.
2. Проверить `migrations/001_privacy.sql` на тестовой PostgreSQL и существующей схеме, включая каскады. `init_db` применяет SQL транзакционно под advisory lock. При следующем запуске обновлённого backend миграция и первая возрастная очистка выполнятся автоматически; в этой работе к production они не применялись. У роли должны быть нужные DDL/DML-права. Сервер и приложение нужно обновить согласованно: старые сборки без обязательных receipts не пройдут новую гостевую регистрацию.
3. Настроить на Bothost/reverse proxy исключение заголовков авторизации, query с ФИО/группой, тел запросов/ответов, а также реальные сроки журналов и резервных копий, шифрование и доступы. Настроить процедуру, которая не вернёт удалённые аккаунты в эксплуатацию после восстановления старого backup. Код приложения не удаляет логи и копии хостера.
4. Проверить действительность старой DB credential-строки и сменить её при необходимости; отдельно решить вопрос истории Git. Установить `DATABASE_URL` для диагностического скрипта через секреты хостинга.
5. Проверить SDK на физическом Android и условия работы MyTracker в отдельном процессе; утвердить процедуру удаления старой аналитики у получателя и доступы кабинета. Сетевые проверки проводить на разрешённой тестовой установке, включая офлайн-буфер, отзыв и повторное согласие.
6. Проверить production-подпись и итоговый release-артефакт, backup/D2D и отсутствие SDK-трафика до согласия именно в нём. Существующая release signingConfig использует debug signing; ключ production в этой работе не создавался. iOS сборка и поведение Keychain не проверены на Windows.

## Проверки

- `flutter test --no-pub --reporter expanded`: **161 тест, все прошли**. В том числе сохранение дизайна/навигации/форм, прямой авторизации и новые сценарии приватности.
- `python -m unittest test_privacy test_groups -v`: **15 тестов, все прошли**. Реальные маршруты проверены ASGI-транспортом без lifespan; PostgreSQL заменена подставным pool/connection. Это не интеграционная проверка SQL на настоящем PostgreSQL.
- Debug APK успешно собран; Kotlin и XML backup проходят компиляцию. Физическое устройство и фактический SDK-трафик не проверялись.
- В проекте есть исходное предупреждение анализа: `analysis_options.yaml` ссылается на отсутствующий в зависимостях `flutter_lints`. Новая зависимость ради этого предупреждения не добавлялась.
