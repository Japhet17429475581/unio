# Поиск группы при входе

Реализован 14.10.2026. Источник — публичный каталог
https://portal.vspu.ru/schedule/students, а не наличие занятий в расписании.
Однократная проверка реального каталога вернула 629 групп.

## Выпуск

Сначала обновить backend с `groups.py`, подключением router в `main.py`
и проверкой в `auth_api/auth.py`, затем выпускать клиент.
Миграция БД и новые зависимости не нужны. Развёртывание в этой задаче не выполнялось.
Старый backend без `GET /api/v1/groups` не сможет обслужить новый вход:
клиент покажет недоступность проверки, а не пропустит произвольную группу.

## Поведение

- `GET /api/v1/groups` возвращает `{"groups": ["…"]}` с каноническими кодами.
- Каталог собирается по ссылкам институт → уровень → форма обучения → группы.
  Страницы расписаний отдельных групп не запрашиваются. Только тот же origin/path,
  до 128 страниц, до четырёх параллельных запросов, общий предел 50 секунд.
- Полный каталог кешируется в памяти процесса на 6 часов. Одновременные обращения
  используют одну загрузку. После ошибки повтор отложен на 60 секунд.
- Частичный или устаревший после неудачного обновления каталог не применяется для
  отказа «неверная группа»: возвращается 503 `group_directory_unavailable`.
- Гостевой и legacy portal auth проверяют группу до записи пользователя в БД;
  неизвестная группа — 422 `unknown_group`. Пустая неделя не влияет на проверку.
- Подсказки клиента ищут по части кода/номеру, без регистра и разделителей,
  с поддержкой английской раскладки русских клавиш. До шести вариантов.
  Вход допускает только полный однозначный код; частичный запрос нужно выбрать
  из списка. После выбора используется точное написание из каталога.
- Полный вход через текущий клиент по-прежнему отправляет университетский пароль
  непосредственно порталу. Проверка группы не передаёт пароль в UNIO API.
- Уже сохранённые сессии не удаляются и не перепроверяются при bootstrap.

## Проверки

`python -m unittest test_groups -v` из `lib/backend`: обход каталога, кеш,
сбой одной ветки, неверная группа, отсутствие записи в БД при отказе.
Flutter: `groups_test.dart`, `welcome_screen_test.dart`, `direct_portal_test.dart`,
`gradebook_portal_test.dart`. Сетевые вызовы и учётные данные в тестах подменены.
